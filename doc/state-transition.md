# 状態遷移図

## 対象

現行実装における、利用者の認証、駐輪場情報の登録・編集、お気に入り操作のフローを示す。図は Mermaid 形式で記述しており、GitHub や Mermaid 対応エディタで表示できる。

## 駐輪場登録・編集フロー

```mermaid
stateDiagram-v2
    [*] --> 未認証
    未認証 --> 認証済み: ログイン / 会員登録
    認証済み --> 未認証: ログアウト

    state "駐輪場登録" as create {
        登録開始 --> 入力中: create
        入力中 --> 入力中: 郵便番号から住所補完
        入力中 --> 入力エラー: 入力不備
        入力エラー --> 入力中: 修正
        入力中 --> 住所確認中: confirm
        住所確認中 --> 入力エラー: ジオコード失敗
        住所確認中 --> 登録確認待ち: 住所・緯度経度確定
        登録確認待ち --> 入力中: 戻る
        登録確認待ち --> 登録済み: store
        登録確認待ち --> 入力中: セッション欠落・期限切れ
        登録確認待ち --> 登録確認待ち: 保存失敗・再試行
        登録済み --> [*]
    }

    state "駐輪場編集" as edit {
        編集開始 --> 編集中: edit
        編集中 --> 編集中: 既存データ読込・修正
        編集中 --> 編集エラー: 入力不備
        編集エラー --> 編集中: 修正
        編集中 --> 住所確認中2: confirm
        住所確認中2 --> 編集エラー: ジオコード失敗
        住所確認中2 --> 更新確認待ち: 住所・緯度経度確定
        更新確認待ち --> 編集中: 戻る
        更新確認待ち --> 更新済み: update
        更新確認待ち --> 編集中: ID不一致・入力改ざん
        更新確認待ち --> 編集開始: セッション欠落・期限切れ
        更新確認待ち --> 更新確認待ち: 保存失敗・再試行
        更新済み --> [*]
    }

    認証済み --> 登録開始: 登録画面
    認証済み --> 編集開始: 編集画面
    認証済み --> 詳細表示: 詳細画面
    詳細表示 --> [*]
```

登録・編集の確認状態はサーバー側セッションで管理し、確定成功時だけ破棄する。確定POSTにはDB更新に必要な値を持たせず、セッション内の確認済み入力を使用する。編集対象IDと一時画像パスはセッションの信頼済みコンテキストと照合し、不一致の場合は保存しない。二重送信では最初の成功後にセッションがなくなるため、2回目は入力画面へ戻す。

## お気に入り操作フロー

```mermaid
stateDiagram-v2
    [*] --> 未登録
    未登録 --> 登録済み: 詳細・トップ・検索一覧から追加
    登録済み --> 未登録: 詳細・トップ・検索一覧・お気に入り一覧から解除
    登録済み --> お気に入り一覧: 一覧を表示
    お気に入り一覧 --> 登録済み: 駐輪場詳細を表示
```

お気に入りの追加・解除・一覧表示にはログインが必要で、操作対象はログインユーザー自身のお気に入りに限定される。

## 料金入力の検証サブフロー

```mermaid
flowchart TD
    A[料金帯を入力] --> B{基本形式・範囲が有効か}
    B -- いいえ --> E[入力エラーを表示]
    B -- はい --> C{同じ曜日区分で時間帯が重複するか}
    C -- はい --> E
    C -- いいえ --> D[確認画面へ進む]
    E --> A
```

料金帯は 1〜4 件、料金単位・曜日区分は設定値に制限される。開始時刻と終了時刻が同じ場合は終日、終了時刻が開始時刻より前の場合は日付またぎとして扱う。
